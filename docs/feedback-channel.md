# «הצעה לשיפור או באג» — канал замечаний сотрудников

Решение владельца, 2026-10-08. Сотрудники не получают доступа к Claude.
Они пишут замечание на сайте, а решает всегда владелец.

## Как это работает

1. Владелец выдаёт право **feedback.submit** конкретным людям на экране
   «אבטחת מידע» (по умолчанию оно не выдано никому; superadmin может всегда).
2. У этих людей в шапке появляется кнопка «הצעה לשיפור או באג» (на телефоне —
   в меню пользователя). Форма: тип (баг / предложение), текст, до 5 скриншотов
   (кнопкой или Ctrl+V в поле текста). Путь текущего экрана уходит вместе с замечанием.
   Скриншоты сжимаются ещё в браузере (длинная сторона до 1920 px, JPEG) —
   `lib/feedback/shrink.ts`; вместе не больше 4 МБ (лимит запроса Vercel — 4,5 МБ).
3. Замечание сохраняется в `feedback_reports` (скриншоты — приватный бакет
   `feedback`). Само по себе оно ничего не меняет.
4. Раз в день (и когда владелец попросит) Claude забирает новые замечания через
   `GET /api/agent/feedback` и приносит их владельцу в проект. После решения
   владельца Claude ставит статус через `PATCH /api/agent/feedback/<id>`.
5. Автор видит статус и ответ владельца на экране «ההערות שלי»
   (`/dashboard/feedback`). Владелец видит там все замечания и тоже может менять статус.

Статусы: `new` (התקבל) → `in_review` (בבדיקה) → `in_progress` (בטיפול) → `done` (בוצע) / `rejected` (נדחה).

## Вход для Claude

- `GET /api/agent/feedback?status=new` (или `status=all`) — список с именем
  автора и подписанными ссылками на скриншоты (1 час).
- `GET /api/agent/feedback/<id>/screenshots/<index>` — сам файл скриншота
  (index с 0). Подписанные ссылки ведут на домен Supabase, куда у Claude в
  проекте нет выхода; этот путь отдаёт тот же файл через сайт.
- `PATCH /api/agent/feedback/<id>` с телом `{ "status"?: "...", "owner_reply"?: "..." }`.
- Заголовок `Authorization: Bearer <FEEDBACK_AGENT_TOKEN>`. Переменная
  `FEEDBACK_AGENT_TOKEN` задаётся в Vercel; без неё вход отвечает 503 (fail-closed).
  Токен открывает только чтение замечаний и их скриншотов и смену статуса/ответа.

## Установка

1. Выполнить миграцию `supabase/migrations/20261009160000_feedback_reports.sql`
   в Supabase SQL Editor **до** мержа.
2. Добавить `FEEDBACK_AGENT_TOKEN` (длинная случайная строка) в Vercel → Settings →
   Environment Variables и сделать redeploy. То же значение должно быть доступно
   Claude в проекте.
3. Выдать право «שליחת הצעות לשיפור ודיווח על באגים» нужным людям в «אבטחת מידע».
